## Things about this repo that are now true and were not

**The scaffold is gated on completeness, not just on links.** Gate 3 (`scaffold
self-consistency`) checks that the scaffold's links resolve. It says nothing about whether a
language overlay can actually produce a working repo. `check-seed-set.sh` is that check:
every overlay ships the required artifact set, every seeded `ci.yml` invokes both the gate
script and the fixture harness, and **the seeder is executed** with a missing and an unknown
`--lang` and must exit 2 leaving nothing behind.

**Rule 4 is behavioural on purpose.** A default `--lang` added later would be invisible to any
grep written today, so the rule runs the seeder rather than reading it. `gates/seed.test.sh`
asserts this explicitly: the rule-4 fixture's seeder *contains the string* `exit 2` and is
still caught, so the rule cannot quietly degrade into a textual one.

**Adding a language is now a bounded PR**: one directory under `scaffold/lang/`, and the gate
refuses it until it is complete.

## Gate status

`scripts/check.sh` — **8 gates, all pass**, locally and on CI for #14:

```
✔ gate inputs declared + every caller wired      ✔ seed-set fixtures (proven able to fail)
✔ plugin manifests (claude plugin validate)      ✔ seed sets complete (every language seeds a gate)
✔ language-agnostic spec                          ✔ sync round-trip
✔ links resolve (+ vendored-set rule)             ✔ scaffold self-consistency
```

`gates/seed.test.sh` — 11 assertions: clean passes, rules 1–4 each fail **and fire exactly one
rule**, a missing scaffold exits 2 rather than 0 or 1.

The overlay itself was verified end to end by its first consumer rather than by assertion:
[xal-org run 35085906470](https://github.com/xodeeq/xal-org/actions/runs/35085906470) — the
seeded `check.sh` green across all ten gates, and the seeded fixture harness showing
`failing-gofmt` exit 1 naming the format gate, `failing-coverage` exit 1 naming the coverage
gate, `clean` exit 0.

## What's next in this repo

Nothing is queued. `CLAUDE.md`'s "Next" list is the standing queue and now reads: the `infra/`
Terraform modules; the `.claude/` sync-scope ADR; the xal-stripped export; and **a second
`scaffold/lang/` overlay** when a service picks a language other than Go.

**When that second overlay lands, look hard at the `common/` / `lang/` split.** It has been
exercised exactly once, by the language it was designed against, which is the weakest possible
evidence that it is in the right place. `ci.yml` is the most likely thing to be on the wrong
side: it is language-specific today, but most of its body is boilerplate — checkout, the
platform checkout, run the gate, run the harness — with only the toolchain steps varying.
This is ADR-0006 revisit trigger 1.

## Open questions / residuals

- **Seeding is a one-shot copy and nothing diffs a seeded repo against the scaffold it came
  from.** Deliberate — the gate script is a starting point a service **owns**, unlike `spec/`,
  which is a contract it keeps tracking. Extending `sync/` to cover the gate script would mean
  a service could not adapt its own gate, which is worse. But it is a real exposure and it is
  where a future "why is auth's gate different?" will lead.
- **`check-gate-inputs.sh` is now third-order**: canonical in xcos-core → vendored here →
  copied from here at seeding. Seeding from this repo's own copy rather than adding a second
  copy inside the scaffold means no new replica pair, but cross-repo drift between the three
  is still detected agent-side only. Already open in xal-company ADR-0005's 2026-09-15
  addendum; not re-filed here.
- **Non-service repos are unreached.** `xal-site` has no gate. ADR-0006 §Scope says so rather
  than claiming the gap is closed.
